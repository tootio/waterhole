# Security policy

## Reporting a vulnerability

Please do not report security issues in public issues, pull requests or discussions.
Tell us privately instead:

* use GitHub's [private vulnerability reporting](https://github.com/tootio/waterhole/security/advisories/new)
  ([how it works](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately)), or
* email [hosting@toot.io](mailto:hosting@toot.io).

It helps if your report includes:

* what an attacker could do, and who is affected (moderators, applicants, instance
  administrators, the operator of a Waterhole)
* the steps to reproduce it, or a proof of concept
* the version or commit you tested

Please give us a chance to fix the issue before you disclose it publicly.

## Supported versions

Waterhole is still before 1.0. Security fixes go into the latest release only, so
please check that the issue is still present there, or on `main`.

## Scope

This policy covers the Waterhole code in this repository. For a problem with a
particular Waterhole deployment, contact its operator. For the Waterhole at
waterhole.toot.io, that is us, at the addresses above.
